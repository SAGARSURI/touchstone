# Phase 3 step 7: A7, results

Scored against [a7_expectations.md](a7_expectations.md) as written, with
`tool/score_a7.dart`. The device is an iPhone 17 Pro simulator (iOS 26.5) on
`macos-latest`, run by the `a7-device` workflow on 2026-10-09; the tool's
side ran on that runner and in the project container (Linux x64), with
identical results on both, seed for seed.

### The three default-font misses

All on `matrix/settings_small` (320 x 568 at 2x): seed 26 (`padding 1px`),
93 (`text colour` on an icon) and 179 (`font weight` on an icon). With the
test font, whose glyphs are each a full em wide, the settings rows above
wrap onto more lines, and the mutated row is laid out at y = 604 to 612,
below the 568 px viewport, so the widget test never draws it. With Roboto,
in the real-font run and on the device, the row is on screen and its change
is reported. This is the wrapping limit the spec names, and it is why A7
holds only with real fonts loaded.

## Scored against the expectations

1. **Real fonts, 0 misses: held.** 0 of 197.
2. **Default font, 0 misses: wrong.** 3 misses. The written reason, that
   the generator never lengthens text, holds, but the test font itself wraps
   text more than Roboto and pushes rows out of view. All three are
   wrapping, so the spec's criterion for the default font is met.
3. **The reverse, a few: more than a few.** 26 with real fonts. 23 of them
   changed no pixel and no semantics in the widget test either: 8 reordered
   children, 3 paddings, 3 sizes and 3 transforms by 1 px, 2 shape colours
   with zero alpha, 2 text changes, 1 font weight and 1 painter removed. The
   tool reports them because the structure or paint it records changed;
   why each one draws nothing different was not traced, beyond the zero
   alpha. The other 3 changed pixels in the widget test (Skia) and not on
   the device (Impeller): seeds 185 and 275 shift the blue of a shape drawn
   at 12% opacity by 2/255, and seed 295 widens a box by 1 px on
   `matrix/settings_large`.
4. **At least 95% matched: held.** 294 of 300 (98%). Four seeds on
   `matrix/settings_text_2x`, where the device and the real-font run agree
   and the default font builds a different tree; seed 84, whose mutated text
   holds the clock time and the device's clock is not fixed; and seed 150 on
   `live/flashing`, whose colour is mid-animation.
5. **No scene noisy on the device: wrong.** `live/flashing`, `live/ticked`,
   `order/transition` and `states/loading` animate in real time under the
   live test binding, so two rasters in a row can differ. Their seeds are
   left out when the double raster catches it; the test cannot hold time
   still on the device.

## Changes from the written method, and the runs before this one

- **No overscroll indicator in either run.** Material's stretch indicator
  is a transform under Skia and a shader filter under Impeller, so the same
  seed picked a different mutation on the device. Found in a Linux desktop
  dry run before any iOS run; both A7 runs set a scroll behaviour without it
  (`a7ScrollBehavior`).
- **The device's insets are zeroed.** The widget tests' view has none; the
  simulator has a 62 px top inset. iOS run 2 laid every scene out below it,
  which changed which list rows were built and the mutation 22 seeds picked;
  its output is kept in [a7_ios_run2/](a7_ios_run2/) and not scored. Run 2
  also showed one apparent real-font miss, seed 21 on `live/ticked`: a flex
  alignment change that changes nothing in either widget-test run, seen on
  the device because a price ticked between the rasters. In run 3 the same
  seed is caught as noisy.
- **iOS run 1** built the app and printed nothing more for two hours, until
  the job's time limit. The workflow now runs a three-seed probe first, with
  step time limits; runs 2 and 3 completed.
- **Linux desktop dry run** (`a7_linux/device_linux_desktop.txt`, not the
  spec's device): the same conclusions, 0 real-font misses of 198 and the
  same three default-font misses.

## What A7 does not show

A simulator, not a phone. One device size, the scenes' 390 x 844 viewport,
and one platform's renderer. Mutations of single render objects, not
whole-screen changes. The animated scenes are not scored on the device.
