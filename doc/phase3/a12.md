# Phase 3 step 6: A12 and change 10, results

Scored against [a12_expectations.md](a12_expectations.md) as written. The
migration is change 10 of the catalogue history: Flutter 3.47.6 to 3.47.7.

## Linux run

Run on 2026-10-09 in the project container (Linux x64), on a scratch copy of
the catalogue at 56905e4 whose 41 baselines were first recorded on 3.47.6.
`dart run touchstone:migrate --from <3.47.6 flutter> test/snapshots_test.dart`
with 3.47.7 on the PATH took 55 s. Output in
[a12_linux/migration.log](a12_linux/migration.log); the 41 proofs in
[a12_linux/proofs.txt](a12_linux/proofs.txt).

| Number | Result |
| --- | --- |
| Snapshots routed to migration | 41 of 41 (flutter, framework and engine differ; Dart is 3.13.5 on both) |
| Pixels identical on both releases | 41 of 41 |
| Root hash changed | 0 of 41: each rewritten baseline differs from the old one only in its toolchain line |
| Review against the pre-migration commit | 41 pass, 0 needs-review, 0 fail |

Two snapshots have the same view digest on both releases and with each
other: `live/initial` and `live/ticked`. Their prices differ, but the test
font draws every glyph as the same box, so prices of the same length give the
same pixels.

## macOS run

Run on 2026-10-09 by the `a12-migration` workflow on `macos-latest` (macOS
arm64), on the committed catalogue baselines at e1e47f5. The first run
migrated, but its output file was ignored by git and the commit step failed;
the second run, on branch `a12-migration/run2`, committed the migrated
baselines and the output (434a703). Output in
[a12_macos/migration.log](a12_macos/migration.log); the 41 proofs in
[a12_macos/proofs.txt](a12_macos/proofs.txt). Nothing from that branch is
merged: the committed baselines stay on 3.47.6, the toolchain CI runs.

| Number | Result |
| --- | --- |
| Snapshots routed to migration | 41 of 41 |
| Pixels identical on both releases | 41 of 41 |
| Root hash changed | 0 of 41 |
| Review against the pre-migration commit | 41 pass, 0 needs-review, 0 fail |

Besides the toolchain line, three rewritten baselines differ in one
explanation field, which is not hashed. `order/amount`, `order/dragging` and
`order/review` record the back button's `RawTooltip.positionDelegate` in
`style` as the closure's description, which names a private function with
its library's number: `_getDefaultPositionDelegate@657220820` on 3.47.6 and
`@659220820` on 3.47.7. The Linux run did not show it. A same-toolchain diff
never compares these, but a style value that names a library number is noise;
it goes to the regression set to be normalised.
