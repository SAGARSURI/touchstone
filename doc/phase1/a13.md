# A13: conventional golden tests through the determinism gate

Assumption A13: "Existing golden tests can be made deterministic". Experiment:
write conventional golden tests for the catalogue app and run the determinism
gate over them. Pass criterion: each failing test gets a message naming the
first differing node and its cause, such as an animation, the clock or an
image load.

**Result (7 Oct 2026, Linux): passes.** 15 conventional golden tests, one
per catalogue state, written the usual way (pump, settle,
`matchesGoldenFile`). The gate fails 4 of them and every failure
names a node and a cause. With the test helpers (`precacheImages`, capture at
a pumped time) all 15 pass the gate and are the recorded snapshot
baselines. Code: [conventional_goldens_test.dart](../../corpus/catalogue_app/test/a13/conventional_goldens_test.dart);
data: [a13.json](a13.json). Re-run on 8 Oct 2026 after the Phase 1 review
fixes: the same 4 tests fail with the same nodes and causes. The goldens are
now recorded on macOS; on another host all 15 PNGs differ, which the test
records as a result rather than a failure.

## Notes

- The detail goldens are a hidden race, not a visible bug. The image bytes
  decode on the real event loop, and `matchesGoldenFile` happens to give them
  time while it rasterizes, so the PNG shows the image in this run. Whether it
  does depends on timing. The gate refuses the capture because the image was
  not decoded when the test reached its golden.
- The loading state animates forever, so a conventional test pumps a fixed
  time. The gate traces the scheduled frame to the shimmer by capturing twice,
  100 ms apart. Declaring the pumped time (`atPumpedTime`) makes it pass.
- None of the 15 catalogue states reads the wall clock, so this run has no
  clock failure. The clock path is covered by the library's own tests only: a
  component reading `package:clock` is named, in its widget class or its
  `State` class, and `withFixedClock` passes. An earlier version of this note
  also credited scripted change 6; that was wrong, since change 6 makes a
  spinner animate forever and reads no clock, and the review found that a
  read in a `State` class named no node until it was fixed.
